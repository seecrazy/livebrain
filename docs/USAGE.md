# 值守手册（LiveBrain 运营 SOP）

> 面向直播间运营/值守人员。产品定位是**人机协同**：AI 讲解与兜底，人工做判断与异常处理。
> 系统设计原则：该自动的自动（隔离/拦截/降级/审计），该人的交给人（接管/恢复/承诺补救）。

## 一、开播前检查清单

| # | 检查项 | 怎么做 | 不过会怎样 |
|---|---|---|---|
| 1 | 直播间数据（**全部选填**） | `python3 -m livebrain.console --data my_room.json --format <场景>`：电商备 products/knowledge；唱歌备**授权曲库白名单**（⚠唯一必选：AI 不能替你拿版权）；相声备段子/对词本；聊天备话题库。**不填时 AI 自动创作**（`--creative` 或 `--real-llm`），失败回落内置；优先级：用户内容 > AI 原创 > 内置种子 | 缺字段/零价格/缺包袱/非法角色启动即报错——开播前发现好过直播中翻车 |
| 2 | 大模型（可选） | `--real-llm` + 环境变量 `ARK_API_KEY`、`LIVEBRAIN_LLM_BASE_URL`、`LIVEBRAIN_LLM_MODEL` | 未配置时中轨走兜底话术池，直播不中断 |
| 3 | 合规门禁 | 启动即自动校验：平台报备、形象授权（真人底模须未过期肖像授权）、AI 标识武装 | 任一不过**拒绝开播**（这是特性不是故障） |
| 4 | 值守端 | 浏览器开 `http://127.0.0.1:8765`，或 `mac/run.sh`（⌘T 接管热键） | — |

知识库健康度：开播前过一遍卖点/FAQ 是否覆盖主推问题；直播后用"未回复问题清单"补录。

## 二、值守大屏解读

| 区域 | 看什么 | 含义 |
|---|---|---|
| 顶栏 chips | 阶段/人设/模式/在线/当前品/LLM | 模式橙色闪烁=真人在场；绿色=AI 主播 |
| 审计徽标 | `审计链 ✓ N 条` | 实时哈希链校验；变红=审计异常，立即排查 |
| 直播画面区 | 数字人球体 / 真人 LIVE 条纹 / 顶部 AI 标识 | 画面源与标识叠加状态与推流一致 |
| 弹幕流 | 标签：价格(蓝)/咨询(绿)/互动(灰)/敏感(橙)/诱导(紫)/**注入(红划线)** | 红色已被消毒器隔离，**无需处理**，仅观察攻击量 |
| 话术时间线 | 快轨/中轨/模板/兜底 + ⚡打断 + 触发来源 | 价格类必为快轨（规则引擎逐字匹配）；兜底出现=LLM 链路异常 |
| 承诺队列 | pending/fulfilled/重试次数 | pending 堆积=平台动作 API 异常，见"异常处理" |
| 告警栏 | JUDGMENT / REHANDOFF_BLOCKED / PIPELINE_ERROR 等 | 见下表 |

## 三、操作时机（什么时候动手）

| 信号 | 动作 | 为什么 |
|---|---|---|
| 橙色判罚横幅出现 | 评估违规内容 → 需要时**接管**改口 → 处理完点**确认恢复** | 平台判罚后 AI 自动降权只说保守模板，恢复需人工确认（不自动恢复是设计） |
| 想真人讲主推品 | 大红键/**T 键**接管 → 讲完**交回** | 接管时 AI 静默+画面交叉淡化切真人；被打断的排队话术自动清空 |
| 交回被挡（REHANDOFF_BLOCKED） | 看承诺队列：人工补执行（如手动上链接）后再交回，或 force 放行 | AI 说过的"上链接/发券"必须核销，防空头支票 |
| 系统进入逼单期（话术变紧迫） | 无需动作；观察上链接原子是否核销 | 库存<20% 自动触发，价格问题优先级自动提升 |
| 弹幕问功效/治病类 | 无需动作 | 敏感问题走固定拒答模板，零生成 |
| LLM 徽标变 mock_llm_backup | 观察兜底话术质量；按需切换主模型 | 主模型熔断自动切备用，直播不中断 |
| 想演示混播 | **应用演示排班**按钮 | 25s AI → 20s 真人 → 25s AI 自动轮转 |

快捷键：网页端 **T=接管、R=交回**；Mac 端 **⌘T / ⌥⌘R / ⌥⌘A（判罚后恢复）**。

## 四、异常处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 启动报"形象资产未通过开播门禁" | 真人底模无/过期肖像授权，或该平台未绑定报备 | 补授权文件或换已报备形象 |
| 启动报"平台未完成开播报备" | 平台报备开关未过 | 完成平台报备流程 |
| 画面区出现"⚠标识未武装" | AI 标识门禁未武装 | 重启控制台（正常流程自动武装；出现即属配置异常，禁止开播） |
| 话术全是兜底（橙） | LLM 链全熔断或超时 | 检查端点/凭据；兜底池可撑场，按需接管 |
| PIPELINE_ERROR 告警 | 推流管线异常 | 优先接管真人，再排查日志 |
| 承诺长期 pending | 平台动作 API 拒绝/异常 | 人工补操作后核销；连续失败检查平台侧权限 |

## 五、直播后复盘

```bash
# 1) 本场弹幕回放回归（四不变量：哈希链/注入隔离/出稿干净/承诺核销）
python3 tools/replay.py record --out session.jsonl
python3 tools/replay.py check  --in  session.jsonl

# 2) 红队集全量回归（改过话术/词表/提示词后必跑）
python3 -m pytest tests/test_redteam_corpus.py -q

# 3) 审计核查（监管/平台申诉口径）：控制台徽标 ✓，或读取审计 JSONL 验链
```

复盘关注三个数：回检拦截率（幻觉监控，目标 <3%）、注入隔离条数、兜底触发次数。
持续偏高 → 补知识库 / 换模型 / 查平台 API。

## 六、娱乐场景值守（V4.4：聊天/唱歌/相声/脱口秀）

启动加 `--format`：`chat`（聊天陪伴）/ `music`（唱歌演艺）/ `standup`（单口相声·脱口秀）/ `crosstalk`（多人相声）。

| 场景 | 大屏会看到 | 值守要点 |
|---|---|---|
| 聊天陪伴 | 阶段显示"话题进行中"，冷场自动抛话题（话题库可 `--data` 自备） | 话题不合场就接管亲自带；礼物自动感谢 |
| 唱歌演艺 | "点歌演唱中"，弹幕出现`点歌`标签 | **版权白名单即授权曲库（`--data` 自备）**：点白名单外的歌会自动婉拒（这是合规红线，不要绕）；点歌按先后顺序报幕 |
| 单口相声·脱口秀 | "段子进行中"，setup+包袱两句结构（段子库可 `--data` 自备） | **被打断的段子会自动回炉重讲**；观众刷"讲个段子"即时应答 |
| 多人相声 | "正活进行中"，A 逗哏/B 捧哏对词轮转（对词本可 `--data` 自备） | 双形象同台属 M3 双主播通道；现在为单形象声音轮换；观众刷"来一段/返场"续演 |

通用不变：注入弹幕红色隔离、敏感宣称固定拒答、判罚降权、接管热键、审计链——**娱乐场景防护同权生效**。

## 七、当前边界与升级路径

- **现在就能跑**：弹幕决策、规则引擎价格话术、真实大模型话术（`--real-llm`）、
  混播切换、接管/交回、审计链——全部真实可用，画面为控制台可视化。
- **M3 接入后**：数字人渲染（MuseTalk/SoulX）与真平台 RTMP 推流上线，
  值守操作与本手册完全一致（画面区从可视化变为真实推流画面）。
- Windows/移动原生壳：网页版已覆盖移动浏览器，原生壳评估见 ROADMAP M4。
